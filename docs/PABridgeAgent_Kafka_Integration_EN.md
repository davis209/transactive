# PABridgeAgent Kafka Integration Guide

This document is for third-party systems and Web PA client teams that need to subscribe to PA state changes.

`PABridgeAgent` subscribes to local `PAAgentComms` messages, converts supported messages to JSON, and publishes them to Kafka. Kafka is an event-notification channel, not a replacement for the REST API. Broadcast creation, control, termination, and queries must still use the PABridgeAgent REST API.

---

## 1. Topic Naming and Record Layout

Topic naming rule:

```text
pa.<MessageName>
```

Each Kafka record contains:

| Part | Content |
| --- | --- |
| Topic | Generated by the preceding rule. |
| Key | Broadcast-related messages use the broadcast ID; configuration messages use an empty string. |
| Value | UTF-8 JSON text. |

PABridgeAgent does not wrap JSON values in a common `eventType`, timestamp, location, or message-ID envelope. Consumers determine event type from the topic name. Consumers handling multiple locations must distinguish source locations through separate topic prefixes, separate deployments, or external metadata.

---

## 2. All PA Events and Corresponding Topics

PABridgeAgent currently subscribes to and forwards all PAAgentComms events listed below. One DVA version event is published to one of three topics according to its payload type, resulting in seven output topics.

| Message name | Topic | Key | Source PAAgentComms message |
| --- | --- | --- | --- |
| `BroadcastProgressUpdate` | `pa.BroadcastProgressUpdate` | `broadcastId` | `BroadcastProgressUpdate` |
| `CurrentBroadcastsUpdate` | `pa.CurrentBroadcastsUpdate` | `toBroadcastId` | `CurrentBroadcastsUpdate` |
| `DvaMessagesUpdate` | `pa.DvaMessagesUpdate` | Empty string | `DvaMessagesUpdate` |
| `DvaVersionsUpdate` | `pa.DvaVersionsUpdate` | Empty string | `DvaVersionsUpdate`, complete version records |
| `DvaPublicVersionsUpdate` | `pa.DvaPublicVersionsUpdate` | Empty string | `DvaVersionsUpdate`, public version records |
| `DvaPrivateVersionsUpdate` | `pa.DvaPrivateVersionsUpdate` | Empty string | `DvaVersionsUpdate`, private version records |
| `PrioritySchemeUpdate` | `pa.PrioritySchemeUpdate` | Empty string | `PrioritySchemeUpdate` |

One `DvaVersionsUpdate` PAAgentComms message is published to one of the three DVA-version topics according to its actual CORBA payload type.

## 3. Payload Schemas

### 4.1 BroadcastProgressUpdate

Published when broadcast state, global state, or local zone/train execution state changes.

```json
{
  "broadcastId": "StationDva_001",
  "broadcastState": "Execution",
  "globalState": 0,
  "localProgresses": [
    {
      "zoneKeyOrTrainId": 1001,
      "localState": 0,
      "overridingSourcePriorityForZonesOnly": 0,
      "errorOccurred": false
    }
  ]
}
```

| Field | Type | Description |
| --- | --- | --- |
| broadcastId | string | Broadcast ID. |
| broadcastState | string | Broadcast lifecycle state. |
| globalState | number | PAAgent numeric enumeration for the overall broadcast result or failure state. |
| localProgresses | array | Execution state for every PA zone or train. |
| zoneKeyOrTrainId | number | PA zone key or train ID. |
| localState | number | PAAgent numeric enumeration for the local execution state. |
| overridingSourcePriorityForZonesOnly | number | Overriding source priority, used only by zone broadcasts. |
| errorOccurred | boolean | Whether an error occurred. |

#### localState enumeration values

| Value | Enum name | Meaning |
| --- | --- | --- |
| 0 | `LOCAL_STATE_IN_PROGRESS` | Broadcast in progress. |
| 1 | `LOCAL_STATE_IN_PROGRESS_DWELL_TIME` | Broadcast in progress during dwell/interval time. |
| 2 | `LOCAL_STATE_CONNECTING` | Connecting to the train. |
| 3 | `LOCAL_STATE_TRAIN_READY` | Train ready. |
| 4 | `LOCAL_STATE_CONTINUE_LIVE_ANNOUNCEMENT_REQUIRED` | A live announcement must be continued. |
| 5 | `LOCAL_STATE_COMPLETED` | Completed. |
| 6 | `LOCAL_STATE_ABORTED` | Aborted. |
| 7 | `LOCAL_STATE_FAILED_CYCLE` | Broadcast cycle failed. |
| 8 | `LOCAL_STATE_FAILED_ZONE` | Zone failed. |
| 9 | `LOCAL_STATE_FAILED_OVERRIDDEN` | Overridden by a higher-priority source. |
| 10 | `LOCAL_STATE_FAILED_TRAIN` | Train-side failure. |
| 11 | `LOCAL_STATE_FAILED_CONNECTION_RESET` | Connection reset. |
| 12 | `LOCAL_STATE_FAILED_INTERRUPTED` | Interrupted. |
| 13 | `LOCAL_STATE_FAILED_VERSION_CONFLICT` | Version conflict. |
| 14 | `LOCAL_STATE_FAILED_INVALID_REQUEST` | Invalid request. |
| 15 | `LOCAL_STATE_FAILED_BUSY` | Target busy. |
| 16 | `LOCAL_STATE_FAILED_BUSY_WITH_OVERRIDE_OPTION` | Target busy; an override can be selected. |
| 17 | `LOCAL_STATE_FAILED_CONTINUE_LIVE_ANNOUNCEMENT_TIMEOUT` | TIMS continue-live-announcement request was not received before timeout. |
| 18 | `LOCAL_STATE_FAILED_NO_PERMISSION` | No duty/permission for this train at the current location. |
| 19 | `LOCAL_STATE_TRAIN_FIRST_CYCLE_CANCELLED` | Train first cycle cancelled. |
| 20 | `LOCAL_STATE_FAILED_BAD_COMMAND` | Train returned an invalid/bad command. |
| 21 | `LOCAL_STATE_FAILED_DIFFERENT_ORIGIN` | Origin does not match. |
| 22 | `LOCAL_STATE_FAILED_DIFFERENT_VERSION` | Version does not match. |
| 23 | `LOCAL_STATE_FAILED_MPU_CHANGEOVER` | MPU changeover failed. |

### 4.2 CurrentBroadcastsUpdate

Published when a broadcast is created, removed, or renamed.

```json
{
  "fromBroadcastId": "StationDva_001",
  "toBroadcastId": "StationDva_002",
  "broadcastType": "StationDva",
  "sessionId": "..."
}
```

| Field | Type | Description |
| --- | --- | --- |
| fromBroadcastId | string | Previous broadcast ID. Usually empty when a broadcast is created. |
| toBroadcastId | string | New broadcast ID. It may be empty when a broadcast is removed. |
| broadcastType | string | Broadcast type. |
| sessionId | string | Session identifier from the original PAAgent message. Consumers must not use it to invoke REST or CORBA APIs, and should neither log nor display it. |

The current implementation forwards `sessionId`. Because it is sensitive session information, production access to this topic must be restricted; a later version may remove this field.

### 4.3 DvaMessagesUpdate

Published when station DVA-message configuration changes. The payload is an array of records.

```json
[
  {
    "pKey": 1001,
    "locationKey": 12345,
    "id": 12,
    "label": "Next train service",
    "type": "N",
    "tisMessageTag": 101,
    "tisLibrarySection": 1,
    "tisLibraryVersion": 3
  }
]
```

### 4.4 DVA Version Updates

The payloads of `DvaVersionsUpdate`, `DvaPublicVersionsUpdate`, and `DvaPrivateVersionsUpdate` are arrays.

Each record includes `pKey`, `locationKey`, and the applicable version fields:

| Topic | Version fields |
| --- | --- |
| `DvaVersionsUpdate` | `privateAdhoc1` through `privateAdhoc6`, `privatePreRecorded`, `publicAdhoc1` through `publicAdhoc6`, and `publicPreRecorded` |
| `DvaPublicVersionsUpdate` | `publicAdhoc1` through `publicAdhoc6` and `publicPreRecorded` |
| `DvaPrivateVersionsUpdate` | `privateAdhoc1` through `privateAdhoc6` and `privatePreRecorded` |

### 4.5 PrioritySchemeUpdate

Published when the PA priority scheme changes. The payload is a three-dimensional numeric array:

```json
[
  [
    [1, 2, 3]
  ]
]
```

The dimensions are station -> zone -> mode priority.

## 4. Consumption Semantics and Ordering

- The producer publishes asynchronously through librdkafka `rd_kafka_producev` and invokes non-blocking `rd_kafka_poll(0)` after each publish.
- The implementation does not select a partition. Kafka determines partitioning from the topic and key.
- Broadcast messages with the same key normally retain partition-local order by broadcast ID, but there is no global ordering across topics or partitions.
- The current implementation has no application-level retry, persistent outbox, de-duplication ID, or exactly-once delivery guarantee.
- Consumers must tolerate duplicate, out-of-order, missing, and restart-recovery events.
- Consumers should use REST queries as the source of truth, especially after startup, reconnection, or detected event loss.

---

## 5. Security and Deployment Limitations

PABridgeAgent currently configures only `bootstrap.servers`. The code does not provide Kafka client configuration for:

- TLS/SSL;
- SASL username, password, or token authentication;
- ACL configuration;
- Schema Registry;
- custom partitioning;
- delivery callbacks and retry policies.

Before production deployment, security controls must therefore be provided through network isolation, broker and topic ACLs, and TLS termination strategy, or by extending PABridgeAgent Kafka configuration.

---

## 6. Consumer Integration Recommendations

1. Use a dedicated consumer group for the required topics.
2. Subscribe to `BroadcastProgressUpdate` and `CurrentBroadcastsUpdate` for broadcast state; subscribe to DVA and Priority topics only when configuration caching is needed.
3. Aggregate broadcast state with `broadcastId` as the key.
4. Record topic, partition, offset, and consumer timestamp in the consumer's own logs for diagnosis.
5. Do not log, display, or use `sessionId` from `CurrentBroadcastsUpdate`.
6. On initial startup or recovery, rebuild the broadcast and configuration baseline through REST query APIs before consuming Kafka incremental events.
